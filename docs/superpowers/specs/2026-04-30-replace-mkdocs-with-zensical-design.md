# Replace MkDocs with Zensical — Design

**Status:** Draft  
**Date:** 2026-04-30  
**Author:** pirhoo + assistant  
**Predecessor spec:** [2026-04-30-mkdocs-documentation-design.md](2026-04-30-mkdocs-documentation-design.md)

## Summary

Replace MkDocs/Material with [Zensical](https://zensical.org/) as kuroi's documentation toolchain. After this change, the project has a single docs-config source of truth (`zensical.toml`), no `mkdocs*` Python dependency, and a deterministic dev-time pipeline that pre-generates the auto-derived reference pages (CLI, rule schema) into committed markdown files which Zensical renders unchanged.

The migration is a clean break: no parallel toolchain, no soft fallback to `mkdocs.yml`. CI enforces drift between code and the generated reference pages.

## Motivation

- MkDocs has been unmaintained since August 2024; supply-chain and security risk grows the longer it stays in the toolchain.
- Material for MkDocs has entered maintenance mode (≥12 months of bugfix-only support). Zensical is the official successor from the same team.
- Zensical natively supports the markdown content kuroi already ships, plus mkdocstrings (preliminary). Two MkDocs plugins kuroi relied on (`mkdocs-typer2`, `mkdocs-gen-files`) are not available in Zensical, but their output is reproducible by Python scripts that write directly into `docs/`.

## Decisions (locked in via brainstorming)

1. **Clean break to `zensical.toml`.** Drop every `mkdocs*` package and the `mkdocs.yml` config file. Do *not* rely on Zensical's ability to read `mkdocs.yml` natively, even though it can.
2. **Pre-generate the auto-derived reference pages and commit them.** `docs/reference/cli.md` and `docs/reference/rule-schema.md` live in git, regenerated by `make docs-gen`, drift-checked by CI.
3. **Brand-equivalent theming, not pixel-equivalent.** Configure Zensical's theme with dark scheme + ICIJ red accent + Poppins/Noto Sans Mono. Port the existing `extra.css` overrides (lifted code background, accent link hover) onto Zensical's CSS custom properties. Do not chase byte-equal layout to the current Material rendering.
4. **Ship mkdocstrings pages as-is.** Accept whatever Zensical's preliminary mkdocstrings support produces for the four `kuroi.core.*` / `kuroi.providers.*` API pages. No fallback to hand-written summaries unless a page is so broken it is unreadable; in that case escalate before merge.

## Scope

### In scope

- New `zensical.toml` translating the current `mkdocs.yml` semantics (site metadata, repo, theme, nav, markdown extensions, mkdocstrings options).
- Deleting `mkdocs.yml`, `docs/_scripts/hooks.py`, and the prebuilt `site/` directory.
- Refactoring `docs/_scripts/gen_rule_schema.py` to write directly to `docs/reference/rule-schema.md` (drop `mkdocs_gen_files` and the `sys.modules` sentinel).
- New script `docs/_scripts/gen_cli_reference.py` that renders `docs/reference/cli.md` from `kuroi.cli:app`, replacing `mkdocs-typer2`.
- New `make docs-gen` target; `make docs` and `make docs-build` depend on it.
- Rewriting `docs/stylesheets/extra.css` against Zensical's CSS variable names while preserving the ICIJ palette and link/code-block tweaks.
- Updating `pyproject.toml` `[project.optional-dependencies].docs` to list only `zensical` and `mkdocstrings[python]`.
- Updating the docs CI workflow to install Zensical, run `make docs-gen`, drift-check the generated files with `git diff --exit-code`, build with `zensical build`, and deploy to GitHub Pages (existing deploy step preserved).
- New tests: a `test_gen_cli_reference.py` covering the new CLI generator, plus a determinism test added to the existing `test_gen_rule_schema.py`.

### Out of scope

- Multi-version docs (no `mike` equivalent right now).
- Switching the deploy target away from GitHub Pages.
- Editing documentation prose; only structural and toolchain changes.
- Adding new pages or features that the current site does not have.
- Pixel-equivalent visual fidelity with the Material theme.

## Architecture

### What goes away

| File / dep | Reason |
|---|---|
| `mkdocs.yml` | Replaced by `zensical.toml` |
| `docs/_scripts/hooks.py` | Existed only to fix an `mkdocs-typer2` × `mkdocs-autorefs` quirk on `reference/cli.md`; with typer2 gone, the workaround is moot |
| Dep `mkdocs` | No longer needed |
| Dep `mkdocs-material` | No longer needed |
| Dep `mkdocs-typer2` | Not supported in Zensical; replaced by `gen_cli_reference.py` |
| Dep `mkdocs-gen-files` | Not supported in Zensical; replaced by direct file writes in the gen scripts |
| Dep `pymdown-extensions` | Zensical bundles equivalent extensions; verify during implementation and remove if not directly imported |
| `site/` | Build artifact; gitignored after migration |

### What stays

- All hand-written content under `docs/`: `index.md`, `user-guide/`, `developer-guide/`, `about/`, `reference/config.md`, `reference/exit-codes.md`, `reference/rule-schema.md` (now committed instead of build-time), `reference/cli.md` (now committed).
- `docs/assets/` (logo, favicon).
- `docs/_snippets/` (used by snippet-style includes).
- `docs/superpowers/` (already excluded from build).
- `mkdocstrings[python]` Python dep — Zensical has preliminary support since 0.0.11.

### What's new or changed

- `zensical.toml` — top-level config, TOML format. Mirrors `mkdocs.yml` semantics.
- `docs/_scripts/gen_cli_reference.py` — new; renders `docs/reference/cli.md` from `kuroi.cli:app`.
- `docs/_scripts/gen_rule_schema.py` — refactored to write directly to disk (no `mkdocs_gen_files`).
- `docs/stylesheets/extra.css` — rewritten against Zensical CSS variables.
- `Makefile` — new `docs-gen` target; `docs` and `docs-build` depend on it.
- `pyproject.toml` — `docs` extra slimmed to `["zensical>=<min>", "mkdocstrings[python]>=0.27"]`. Minimum Zensical version pinned to whatever release first shipped preliminary mkdocstrings (≥0.0.11).
- `.github/workflows/docs.yml` — install Zensical, run `make docs-gen`, drift-check, build, deploy.

## Components

### `zensical.toml`

Translation of the current `mkdocs.yml`. Sketch (exact key paths verified against Zensical's TOML schema during implementation):

```toml
[project]
site_name = "kuroi"
site_description = "Strip sensitive data from PDFs with LLM assistance."
site_url = "https://icij.github.io/kuroi/"
copyright = "Copyright © International Consortium of Investigative Journalists"

[project.repo]
url = "https://github.com/ICIJ/kuroi"
name = "ICIJ/kuroi"
edit_uri = "edit/main/docs/"

[theme]
[theme.palette]
scheme = "slate"
primary = "black"
accent = "red"

[theme.font]
text = "Poppins"
code = "Noto Sans Mono"

extra_css = ["stylesheets/extra.css"]

# nav: translated 1:1 from current mkdocs.yml
# markdown extensions: kept as-is (admonition, attr_list, md_in_html, tables,
#   toc with permalink, pymdownx.details, pymdownx.superfences with mermaid,
#   pymdownx.tabbed, pymdownx.snippets, pymdownx.highlight, pymdownx.inlinehilite,
#   pymdownx.keys)
# mkdocstrings options: paths=[src], google docstring style, show_root_heading,
#   members_order=source, separate_signature, show_signature_annotations,
#   heading_level=2
```

The semantic content is what is locked by this design. The exact TOML key paths are an implementation detail to be confirmed against Zensical's schema (they may differ — e.g., `[theme.colors]` vs `[theme.palette]`).

### `docs/_scripts/gen_cli_reference.py` *(new)*

Imports `kuroi.cli:app` (a Typer app), walks the command tree, and emits a markdown page at `docs/reference/cli.md`.

Contract:
- Top-of-file banner: `<!-- DO NOT EDIT — generated by docs/_scripts/gen_cli_reference.py -->`
- Output written via `Path.write_text(..., encoding="utf-8", newline="\n")`
- Page shape mirrors the current `reference/cli.md` produced by `mkdocs-typer2` closely enough that nav links resolve and the CLI surface is faithfully documented; small layout differences acceptable.
- Idempotency: same input → byte-identical output. No timestamps, no random ordering.
- `render_cli_markdown(app: typer.Typer) -> str` is the testable pure function; `main()` does the file write.

### `docs/_scripts/gen_rule_schema.py` *(refactored)*

The existing rendering logic (`render_schema_markdown`, `_field_table`, `_format_type`) is preserved verbatim. Only the I/O layer changes:

- Remove the `import mkdocs_gen_files` line inside `main()`.
- Replace the `mkdocs_gen_files.open(...)` / `set_edit_path(...)` calls with `Path("docs/reference/rule-schema.md").write_text(rendered, encoding="utf-8")` (path resolved relative to the repo root computed from `__file__`).
- Drop the `if "mkdocs_gen_files" in sys.modules: main()` sentinel at module bottom; replace with `if __name__ == "__main__": main()`.
- Add the `<!-- DO NOT EDIT — generated by docs/_scripts/gen_rule_schema.py -->` banner as the first line of the rendered markdown, *before* the `# Rule schema` H1.

**Banner placement decision:** banner goes at the top of the file, *before* the H1. Update the existing `test_render_includes_intro_paragraph` test to use `re.sub(r"^<!--.*?-->\n", "", out, count=1).lstrip().startswith("# Rule schema")` (or equivalent) so the leading comment is tolerated. The other two existing tests (field presence) are unaffected.

### `docs/stylesheets/extra.css`

Current file targets Material's `[data-md-color-scheme="slate"]` selector and `--md-*` variables. Rewrite against Zensical's CSS variable names (verified by inspecting a default Zensical install during implementation). Preserve:

- Dark base around `#0f1115`
- Foreground `#e6e6e6` / muted `#9a9a9a`
- ICIJ red accent `#d62828`, link color `#ff5a5a`
- Code block background `#15171c`
- "Lift fenced code blocks off the page background without a border" behavior
- Accent-color link hover behavior

If Zensical's defaults already produce a similar dark-base + accent treatment, the rewrite may shrink to just the palette overrides.

### Makefile changes

```make
.PHONY: ... docs docs-build docs-gen

docs: _check-uv docs-gen
	@uv run zensical serve

docs-build: _check-uv docs-gen
	@uv run zensical build --strict
	@echo "Docs build OK (site/)"

docs-gen: _check-uv
	@uv run python docs/_scripts/gen_cli_reference.py
	@uv run python docs/_scripts/gen_rule_schema.py
	@echo "Generated reference pages OK"
```

The `--strict` flag is conditional. If Zensical does not expose it, fall back to plain `zensical build` and rely on warnings-as-errors via configuration if available.

### `pyproject.toml` `[project.optional-dependencies].docs`

```toml
docs = [
    "zensical>=0.0.11",
    "mkdocstrings[python]>=0.27",
]
```

`zensical>=0.0.11` is pinned because that release first shipped preliminary mkdocstrings support per Zensical's docs. Bump the floor only if a newer release is available with relevant fixes at implementation time; never lower it.

### CI workflow (`.github/workflows/docs.yml`)

```yaml
- run: uv sync --extra docs
- run: make docs-gen
- name: Drift check
  run: |
    git diff --exit-code docs/reference/cli.md docs/reference/rule-schema.md \
      || (echo "Generated reference pages are out of date — run 'make docs-gen' and commit"; exit 1)
- run: uv run zensical build
# (existing GitHub Pages deploy step, retargeted at site/ output)
```

The drift check fires when a contributor changes a Typer option or a rule dataclass field without re-running `make docs-gen`. The error points them at the fix.

## Generation flow

### Local

```
make docs        →  docs-gen  →  zensical serve  (live reload on docs/ changes)
make docs-gen                                    (regenerate reference only)
make docs-build  →  docs-gen  →  zensical build
```

### CI

```
uv sync --extra docs
make docs-gen
git diff --exit-code docs/reference/{cli,rule-schema}.md   # drift gate
uv run zensical build
# deploy to GitHub Pages
```

### Idempotency contract

Both gen scripts MUST produce byte-identical output for unchanged inputs. Concretely:

- No timestamps, no UUIDs, no random ordering.
- Stable iteration: `dataclasses.fields()` returns declaration order; Typer's command tree is walked in declaration order.
- Trailing newline at EOF (so `git diff` does not flag missing-newline).
- Banner is fixed text, not `f"<!-- generated at {datetime.now()} -->"`.

## Failure modes

| Failure | Cause | Surface |
|---|---|---|
| `make docs-gen` errors | Import error in `kuroi.cli` or `kuroi.core.rules` | Script raises; CI fails |
| Drift check fires in CI | Code changed without re-running `make docs-gen` | Diff in CI log; message: "run `make docs-gen` and commit" |
| `zensical build` fails | TOML schema mismatch / unsupported option | Build error; fix `zensical.toml` |
| mkdocstrings page renders poorly | Preliminary support gap | Page ships as-is per Q4 decision; no build failure. Escalate before merge if a page is unreadable |

## Testing

### Existing tests (preserved)

- `tests/docs/test_gen_rule_schema.py` — the three existing tests (`test_render_includes_top_level_fields`, `test_render_includes_category_fields`, `test_render_includes_intro_paragraph`) keep passing. `test_render_includes_intro_paragraph` is updated by one line to strip the leading HTML banner before the `startswith("# Rule schema")` check (see "Banner placement decision" under `gen_rule_schema.py`). The other two tests are unaffected.

### New tests

1. `tests/docs/test_gen_cli_reference.py` *(new)*
   - `test_render_includes_banner` — output starts with the `DO NOT EDIT` banner.
   - `test_render_includes_top_level_commands` — output mentions every top-level command name registered on `kuroi.cli:app`.
   - `test_render_is_deterministic` — calling `render_cli_markdown(app)` twice returns identical bytes.
2. `tests/docs/test_gen_rule_schema.py`
   - Add `test_render_is_deterministic` — calling `render_schema_markdown()` twice returns identical bytes.

### Manual verification (during implementation)

1. `make docs-gen` produces files broadly equivalent to the current MkDocs-rendered output (spot-checked against the current `site/` before deletion).
2. `make docs` serves locally; all nav entries reachable; no console errors.
3. Search box works (Zensical's built-in search).
4. mkdocstrings pages render. Accept Zensical's preliminary output, escalate if unreadable.
5. Theme: dark base, ICIJ red accent visible on links/hover, Poppins/Noto loaded.
6. CI passes on a draft PR before merge.

## Rollout

Single PR. The cutover is atomic — once `mkdocs.yml` is gone the old toolchain does not work, and once `zensical.toml` is in, CI uses the new path. Splitting into "add Zensical alongside" then "remove MkDocs" buys nothing because nobody is consuming the docs locally during the cutover window.

If anything in the manual verification gates looks bad, pause and surface before merge.

## Open questions and risks

- **Zensical TOML schema specifics.** Exact key paths (e.g. `[theme.palette]` vs `[theme.colors]`) and option names will be verified against Zensical's documentation during implementation. The semantic intent in this design is locked; the syntax may shift.
- **`zensical build --strict` flag.** Existence not yet confirmed. Fallback: plain `zensical build` plus drift check.
- **mkdocstrings rendering quality.** Preliminary support means some features (cross-reference backlinks, certain autoref patterns) are missing. If a page is so broken it harms the docs, escalate before merge per Q4 decision.
- **`pymdown-extensions` dep.** Zensical bundles equivalents but the dep may still be imported indirectly. Verify during implementation; remove only if no import path needs it.
- **Snippet base paths.** Current `pymdownx.snippets` config uses `base_path: [docs/_snippets, .]`. Verify Zensical preserves this configuration shape.
